    Project Status And Remaining Work

    Last reviewed: 31 October 2026

    This page is the current evidence-based view of ai-memory-hub. GitHub issues, not Markdown checklists, own unfinished work. Historical plan documents may explain design decisions, but their unchecked boxes are not the backlog.

    The classification below was reconciled against runtime code, tests, workflows, the current GitHub issue history, and repository settings. A capability is:

    • Done when it is implemented, covered by representative tests, and exposed through the documented surface.
    • Partial when a useful slice ships but a material part of the intended outcome remains.
    • Not started when only design text, compatibility scaffolding, or adjacent infrastructure exists.

    Executive Summary

    The service foundation is substantially complete. ai-memory-hub already ships schema-first ingestion, deterministic deduplication, HTTP/MCP/CLI workflows, pluggable metadata and vector storage, auth and project isolation, importers, fact and temporal projections, handoffs, observability, quality gates, container and documentation automation, and a tested Connect UI.

    The remaining work is concentrated in productization and advanced capabilities: release enforcement, plugin packaging, message-level model provenance, provider-login hardening, app-level encryption, the remaining import/capture matrix, user-facing memory management, SDKs, advanced intelligence and graph features, Neo4j/provider expansion, and measured operational efficiency.

    Done

    Capability Evidence
    Core ingestion and deterministic storage HTTP/MCP/CLI insert paths, schema validation, hashing, append/re-import reconciliation, chunk manifests, and unit/integration coverage.
    Search, retrieve, ask, and response shaping Hybrid retrieval, filters, rank fusion/reranking, token budgeting, citations, concise/detailed formats, and retrieval quality benchmarks.
    Fact, profile, and temporal foundations Derived facts, supersession, latest-value projection, timelines, generated summaries, provenance, and profile/fact APIs and MCP tools.
    Handoff memory Retrieval-only and stored handoffs, lineage, source/workspace provenance, resume hints, HTTP/MCP/CLI surfaces, and safety coverage.
    Auth and collaboration baseline Bearer and OAuth resource-server modes, external OIDC validation, owner/project isolation, roles, consent, durable OAuth state, and audit events.
    Storage abstraction baseline SQLite/Postgres/MongoDB metadata and fourteen advertised vector providers with capability checks, fallback behavior, dry run, and provider tests.
    Import platform Registry-backed import API/CLI/UI, compatibility reporting, safe latest discovery, stable imported-session identity, and importers for major local-agent formats.
    Observability baseline Structured logs, request/trace correlation, health/readiness/observability endpoints, OpenTelemetry instrumentation, metrics, and a local observability stack.
    Engineering and release automation baseline Ruff, Pyright, pytest, Bruno, CodeQL, dependency review, container smoke, image scanning/SBOM, docs publishing, and Docker publish workflows.
    Completed focused plans Token budgeting, CLI, Bruno, retrieval precision, context building, conversation grouping, MCP response format, edge-case coverage, and beta governance.

    Not Started

    Capability Boundary
    App-level payload encryption and key rotation No encryption service, encrypted metadata columns, migration commands, or encrypted-backup operating model exists. This must remain disabled by default and must not be confused with disk encryption. Tracked in #348.
    Installable Codex plugin package The service is plugin-ready at the MCP boundary, but no .codex-plugin/plugin.json, personal marketplace entry, bundled skills, or plugin lifecycle exists. Tracked in #350.
    Neo4j Aura provider Design and quality-gate scaffolding exist, but there is no Neo4j vector adapter, graph mirror, factory wiring, or live provider test. Tracked in #353.
    General end-user memory dashboard and SDKs Connect/import pages are not a search, browse, review, diagnostics, or developer SDK product surface. Tracked in #351.
    Encrypted multi-device sync Backup/sync/conflict handling remains a later optional program and must preserve local-first defaults.

    Rules Going Forward

    • Put unfinished work in a GitHub issue with acceptance criteria and explicit compatibility boundaries.
    • Keep public docs focused on shipped behavior, setup, operations, architecture, and a short status summary.
    • Do not add new checkbox-based implementation plans under docs/.
    • Close an epic only after its shipped docs and tests match the implementation.
    • Preserve detailed design decisions in an ADR or architecture page when they remain useful after the work is complete.
